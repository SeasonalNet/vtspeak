Stage 176: terminal recognizer context-window construction

Evidence

- Original vt_pau x86 FUN_10063300 (0x10063300-0x100633c7) strips trailing
  ASCII space/tab/LF/CR, then copies backward with a 30*count-1 length gate.
  Each whitespace encounter counts separately, not each lexical token.
  The native gate decrements length before copying, producing a maximum
  copied length of 30*count-2. Returned low short includes stripped trailing
  whitespace; the copied C string excludes that whitespace. All-whitespace
  prefixes return zero, including when trailing bytes were traversed.
- FUN_10063660 (0x10063660-0x1006373d) initializes three 0x44-byte records,
  scans with caller mode and mode pointer zero, advances by scanner +0x14
  rather than the scanner return, and rolls nonempty prior records only while
  another scan remains. It returns short 1 after consuming the string and
  short 0 for an empty string.
- FUN_10051cc0 (0x10051cc0-0x10051ff6) copies backward with count 3,
  adjusts the prior source coordinate by that signed short, scans with mode 1,
  and projects only +0, +0x10, +0x1c and the C string into a zeroed six-record
  window. Current token is copied unconditionally, neighboring records only
  when +0x10 > 0. Following scans use model-state +0x39e8 as mode pointer,
  with positions from current +0x14 then first following +0x14. A invokes
  FUN_10052520 followed by FUN_10001670 at global object 0x100a7a68;
  a nonzero low byte returns P, otherwise N.
