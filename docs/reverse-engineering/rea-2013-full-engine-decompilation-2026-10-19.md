# REA decompilation of the 2013 VoiceText engine

## Scope and target

REA's Ghidra 12.1.4 provider analyzed the local x86 PE `binary/vt_pau.dll`,
SHA-256 `200945bbb2853cc56b3eaa03770eedf26066b20bfc471ef5b0213387035b37ce`.
The target was opened read-only. No DLL code ran and no vendor inputs were
changed. The evidence bundle, a deduplicated pseudocode listing, and an address
inventory are under
[`tools/revkit/work/rea-2013-rest-2026-10-19/`](../../tools/revkit/work/rea-2013-rest-2026-10-19/).

## Coverage result

REA's current Ghidra analysis recognizes 1,187 procedures: 1,098 non-external,
non-thunk engine procedures, 83 external procedures, and 6 thunks. Batch
decompilation succeeded for all 1,098 engine procedures. One 10-function pilot
batch was repeated in the full pass; the exported bundle therefore contains
1,108 successful decompilation records but 1,098 unique procedure addresses.
The extracted C-like listing deduplicates by canonical procedure address.

The earlier coverage report noted that the complete internal-function
inventory had not been measured. This pass closes that inventory and static
decompiler-coverage gap for the procedures Ghidra currently recognizes. It
does not establish that Ghidra found every possible function boundary in the
binary, that each decompilation is correct, or that the DLL's behavior is
understood. Most internal procedures retain autogenerated `FUN_...` names.
Types and control flow are Ghidra pseudocode and require focused assembly,
cross-reference, or runtime checks before semantic claims.

This is broad static coverage rather than a new subsystem reconstruction.
Existing reports already explain selected loader, text, synthesis, file-output,
model-reader, and decoder paths. The full listing makes the remaining
procedures available for targeted follow-up; it does not assign semantic names
to every function. The existing
[`vt_pau-objdump-disassembly.txt`](../../tools/revkit/work/reports/vt_pau-objdump-disassembly.txt)
remains the machine-instruction reference.

## Limits

- Coverage is limited to Ghidra's 1,187 current procedure records and the
  default analysis profile; this is not a proof that all executable bytes are
  correctly partitioned into functions.
- The 83 external procedures and 6 thunks were inventoried, not batch
  decompiled as engine bodies.
- This pass did not trace every call graph, resolve all indirect calls, rename
  functions, or validate every pseudocode body against assembly or runtime
  behavior.
- The DLL, host, and voice assets were not executed. Existing runtime findings
  remain bounded to the fixtures and controls documented elsewhere.
- No implementation code changed, so unit tests and quality checks were not
  run.
